# @davi/nfc-agent-client

The client library for the Davi NFC Agent, in the repository that defines the
protocol it speaks.

There is one implementation. `src/` is the source; the agent's own control
center (`webui/frontend`) imports it, the Davi apps import it, and `dist/` is
the same code built for a page with no build step. A protocol change that
breaks a consumer breaks the console's build in the same commit, which is the
point of the console consuming it rather than talking to `/ws` itself.

```
src/session/types.ts      the wire format, as the agent defines it
src/session/protocol.ts   parsing a tag broadcast, and the base64 the wire uses
src/session/client.ts     NFCClient — the socket, requests, tag targeting
src/session/diagnose.ts   why a connection failed, in operator terms
src/react/                useNFCClient
dist/                     generated by `npm run build`; committed
```

`nfc-device-client.js` is a separate library for the other role — a phone or
Node process acting as a reader for the agent. It speaks the device protocol,
not this one.

## Using it

```ts
import { NFCClient } from "@davi/nfc-agent-client";
import { useNFCClient } from "@davi/nfc-agent-client/react";
```

```html
<script src="dist/nfc-client.js"></script>
```

[docs/javascript-client.md](../docs/javascript-client.md) is the reference;
[docs/api.md](../docs/api.md) is the protocol underneath it.

## Working on it

```bash
npm install
npm test        # vitest, against a fake WebSocket
npm run typecheck
npm run build   # regenerate dist/ — commit the result
```

`dist/` is committed for the same reason `webui/frontend/dist` is: consuming
this library should not require Node.

## Origin allowlisting

The agent rejects WebSocket upgrades whose `Origin` is not its own `host:port` —
that guard is what stops any site the operator visits from driving their reader.
A page served from anywhere else must be listed on the agent:

```bash
davi-nfc-agent -allowed-origins "order.davi.social,localhost:3002"
```

Without it the upgrade fails and `connect()` rejects. Note the agent's REST
endpoints answer `Access-Control-Allow-Origin: *`, so `healthCheck()` succeeds
from any origin — a working health check does not mean the WebSocket will
connect. That is what `diagnoseAgent()` exists to tell an operator.

## Connection model

The agent runs a single listener (default port `9470`). `NFCClient` connects to
the client endpoint via plain `/ws` on that port; NFC readers/devices use the
device endpoint (`/ws?mode=device`) on the same port. Point `serverUrl` at the
shared agent port (e.g. `https://localhost:9470`).
